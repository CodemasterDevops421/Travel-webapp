# Phase 02.3: Homepage Navigation and Detail Shell Regression Closure - Context

**Gathered:** 2026-03-11
**Status:** Planning complete

<domain>
## Phase Boundary

Phase 02.3 closes regressions introduced by the recent homepage motion/design work:
- homepage discovery cards must navigate again
- hotel-detail shell utilities must exist again so the property flow retains its card chrome and layout scaffolding
- regression coverage must protect both behaviors going forward

This phase does not add new discovery capabilities, redesign hotel detail, or expand the homepage information architecture.
</domain>

<decisions>
## Implementation Decisions

### Homepage card navigation
- Restore the previous preference-aware destinations for homepage cards rather than replacing them with generic `/search` links.
- Featured deals, travel journal cards, and trending destinations should behave as actual links again for both mouse and keyboard users.
- The restored behavior should preserve preference-aware navigation semantics through `PreferenceLink` where that was the prior contract.

### Hotel-detail shell utilities
- Restore the legacy hotel-detail utility classes used by the current detail flow.
- Reintroduce `surface-shell`, `surface-shell-subtle`, `page-shell`, and `page-section` in `globals.css` for this regression-closure phase.
- Do not use this phase to migrate all hotel-detail callers to the newer surface utility names.

### Regression coverage
- Add behavior-level tests for homepage card navigation regressions.
- Add focused style-contract guardrails for the restored hotel-detail shell utilities so the missing-class regression cannot recur silently.
- Coverage should be stronger than a smoke check, but remain focused on the exact regressions instead of broad visual re-testing.

### Scope guardrails
- This phase is a regression-closure phase, not a new redesign pass.
- If follow-up cleanup is desirable after stability is restored, capture it later as a separate refactor phase.
</decisions>
