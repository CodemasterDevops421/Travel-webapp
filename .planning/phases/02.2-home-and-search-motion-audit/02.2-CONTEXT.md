# Phase 02.2: Home and Search Motion Audit - Context

**Gathered:** 2026-03-11
**Status:** Ready for planning

## Phase Boundary

This inserted phase focuses on a frontend audit and motion-system refresh for the homepage and search shell only. The goal is to improve visual quality, interaction polish, and motion storytelling on discovery surfaces without changing booking logic, supplier contracts, or hotel-detail information architecture. Hotel detail may reuse motion principles later, but it is explicitly out of scope for this phase.

## Implementation Decisions

### Surface scope
- Phase `02.2` is limited to the homepage, global header/search shell, and search-entry experience.
- The primary code surfaces are `src/app/page.tsx`, `src/components/layout/header.tsx`, and `src/features/search/components/hero-search-bar.tsx`.
- Search results and hotel-detail pages may receive only incidental compatibility adjustments needed to keep the shell coherent; they are not redesign targets in this phase.

### Audit-first approach
- Start with a frontend audit before implementing motion changes.
- Audit should cover layout consistency, spacing rhythm, typography hierarchy, hover/focus quality, shell responsiveness, and motion opportunities.
- Audit should also call out anything that currently feels visually disconnected from the Hostel Stays brand direction, especially in the header/search/homepage relationship.

### Motion direction
- Target animation intensity is **polished**, not dramatic.
- Motion should support travel inspiration and perceived quality without making the booking/search surface feel noisy or slow.
- Use transform/opacity-based motion and avoid scroll-jacking or any interaction that traps normal browsing behavior.
- Respect reduced-motion preferences.

### Provided component adaptation
- The supplied `Hero`, `ScrollExpandMedia`, and `Globe` components are reference patterns, not drop-in components.
- Reuse their ideas selectively:
  - rotating headline / layered hero motion from `Hero`
  - cinematic framed media reveal from `ScrollExpandMedia`
  - atmospheric travel/planet motif from `Globe`
- Adapt them into the existing Hostel Stays visual system rather than introducing a second design language.

### Search shell contract
- The compact search bar must remain usable, legible, and conversion-oriented across desktop and mobile.
- Motion should enhance the search shell but must not make field entry, suggestion picking, or date/guest selection harder.
- The inline desktop header search pattern established on non-home pages should remain intact unless a later dedicated shell phase decides otherwise.

### Visual system guardrails
- Preserve the current product’s premium travel direction, but push it toward a more intentional and memorable identity.
- Avoid generic “AI landing page” aesthetics.
- The phase should define clearer choices for typography, accent usage, gradients, glass effects, and section transitions so the homepage feels designed as one system rather than a collection of cards.

### Claude's Discretion
- Exact animation primitives and sequencing.
- Whether the adapted hero uses rotating copy, layered media, globe motifs, or a combination, as long as the final result feels coherent and conversion-safe.
- Whether audit output is captured as findings inside the plan or as a dedicated markdown artifact before implementation.

## Specific Ideas

- Audit likely focus areas:
  - The homepage hero currently has strong static composition but limited motion identity.
  - The header, homepage hero, and compact search shell feel functionally solid but stylistically under-connected.
  - Current discovery surfaces use premium tokens and shadows, but the brand atmosphere can be more distinctive.
- Candidate animation ideas:
  - rotating value-language in the homepage hero headline
  - restrained staggered reveal on homepage sections
  - soft parallax or media-frame motion for the hero visual block
  - subtle atmospheric/world-travel motif derived from the globe concept
- Avoid:
  - full-page wheel interception
  - mandatory scroll-driven expansion that blocks normal navigation
  - autoplay-heavy motion that competes with search input

## Existing Code Insights

### Reusable Assets
- `src/app/page.tsx`: current homepage hero structure, section order, and editorial-card pattern.
- `src/components/layout/header.tsx`: inline compact search shell and desktop/mobile header boundary logic.
- `src/features/search/components/hero-search-bar.tsx`: existing animated search shell with framer-motion already wired in.
- `src/components/home/*`: homepage content modules that can participate in staggered reveal or visual consistency passes.

### Established Patterns
- The app already uses premium surface tokens (`surface-panel`, rounded containers, soft shadows) that should remain the base system.
- The homepage currently uses fade-in utility classes and a strong shell composition; this phase should evolve those patterns rather than replace them wholesale.
- Search and booking flows prioritize clarity and trust; motion should reinforce those values rather than chase novelty.

### Integration Points
- Homepage hero copy block and media background treatment.
- Search shell entrance, compact-header integration, and suggestion/dropdown feel.
- Section transitions for featured deals, trending destinations, mood discovery, travel articles, and newsletter band.
- Theme and contrast behavior across light/dark modes, especially for translucent surfaces.

## Deferred Ideas

- Hotel-detail storytelling motion belongs in a later dedicated phase, not in `02.2`.
- Any redesign of booking, checkout, or admin surfaces is out of scope.
- Any provider/data changes, new search capabilities, or SEO-route changes are out of scope.
- Any experimental scroll-locking interaction similar to the raw `ScrollExpandMedia` behavior is deferred unless a later phase explicitly approves it.
