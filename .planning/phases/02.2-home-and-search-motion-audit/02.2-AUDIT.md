# Phase 02.2 Audit And Motion Contract

## Scope

This artifact locks the homepage, header, and search-shell design direction before visual implementation begins. It applies to:

- `src/app/page.tsx`
- `src/components/layout/header.tsx`
- `src/features/search/components/hero-search-bar.tsx`

Out of scope:

- hotel detail storytelling
- booking and checkout redesign
- supplier/data contract changes
- scroll-trapped cinematic experiments

## Audit Findings

### 1. Homepage hero has premium structure but limited motion identity

The current hero already has a strong static shell:

- editorial headline with a clear two-line hierarchy
- premium image treatment with a readable dark overlay
- elevated search panel positioned as the primary conversion surface
- supporting proof points and a desktop-only editorial card

What feels incomplete:

- motion language is generic `animate-fade-in`, not a distinct discovery signature
- the hero headline, search shell, and supporting card do not yet behave like one orchestrated system
- the surface reads premium, but not yet memorable

### 2. Header and homepage share function, not enough style rhythm

The header is structurally sound:

- compact inline desktop search on non-home routes
- full header suppression on `/booking`
- clear route-aware shell logic

What feels disconnected:

- the homepage hero search is visually richer than the inline desktop search, but the transition between the two is mostly structural rather than branded
- the shell does not yet communicate one consistent motion story across homepage entry, sticky header presence, and compact search usage

### 3. Search shell is conversion-safe but visually conservative

`HeroSearchBar` already preserves the right priorities:

- stable field positions
- clear destination, date, and guest separation
- compact and default variants
- autocomplete and popover interactions that remain direct

Risks to avoid in later implementation:

- animating the input frame in ways that move hit targets during entry
- adding hero motion that visually overpowers the search bar
- layering decorative effects that reduce contrast or interfere with suggestions/popovers

### 4. Section rhythm is strong enough for staggered reveal, not structural reordering

The homepage has a sensible content sequence:

- hero
- trust/value strip
- editorial discovery modules

The sequence should stay intact. The better improvement is section reveal consistency, not content reshuffling.

## Locked Visual Direction

### Brand posture

The discovery shell should feel:

- premium
- editorial
- calm
- travel-forward

It must not feel:

- hyper-animated
- futuristic-dashboard styled
- generic AI landing page
- gamified

### Typography and composition

- The hero headline remains large, compressed, and high-contrast.
- Rotating or staged copy is allowed only if the first meaningful headline remains immediately readable on load.
- Supporting copy should stay concise and conversion-oriented.
- Section transitions may add pacing, but the homepage must still read as a booking surface first.

### Surface language

- Continue using rounded premium containers, soft borders, and elevated surfaces already established in the app.
- Glass and blur are allowed only as supporting accents around editorial or atmospheric layers.
- The search shell remains the highest-clarity surface in the hero.
- Inline compact search remains flatter and denser than the homepage hero shell, but clearly from the same design family.

## Locked Motion Contract

### Motion intensity

Motion intensity is fixed at **polished / restrained**.

Allowed:

- opacity fades
- subtle translate reveals
- restrained scale on decorative media layers
- staggered section entrances
- gentle headline/value-language cycling

Not allowed:

- large travel-distance transforms on core inputs
- looping motion that competes with search entry
- aggressive spring bounce
- motion that causes content reflow after the page becomes interactive

### Search-shell safety rules

- Destination, date, and guest controls must keep stable target areas during interaction.
- Suggestion lists and popovers must appear above decorative layers without clipping.
- The compact desktop search must remain inline in the header on non-home routes.
- Checkout routes must continue to suppress the global header entirely.
- Mobile search controls must stack without horizontal overflow at 375px.

### Reduced-motion rules

Reduced motion is mandatory for all non-essential animation in this phase.

Requirements:

- decorative hero motion collapses to static presentation
- staged reveals become immediate render or near-zero-duration fade
- rotating copy must stop on a static readable state
- search shell entry must remain stable and readable with motion removed

### Banned interaction patterns

These patterns are explicitly prohibited for Phase 02.2 and any dependent implementation plan:

- wheel interception
- touch interception for faux scroll narratives
- scroll-jacking
- pinned or trapped hero experiences
- autoplay-heavy decorative media
- animated layout shifts that move form controls while focused

## Implementation Constraints For Later Plans

### Homepage hero

- Keep the search shell visually primary above the fold.
- Decorative motion belongs behind or around the search shell, never on top of input affordances.
- If a globe/world motif is introduced, it stays atmospheric and hero-scoped.
- The overlay must remain light enough to preserve contrast between the image field and the elevated search container.

### Header and compact shell

- The compact header search remains dense, inline, and conversion-first.
- Header polish may improve entrance and surface cohesion, but must not convert the compact search into a modal or dropdown-first interaction.
- Mobile navigation may reveal compact search inside the menu, but the control pattern must remain familiar to the existing shell.

### Section reveals

- Homepage modules may use shared reveal timing to improve rhythm.
- Reveals must not delay content discoverability or block scroll.
- Below-the-fold motion should feel editorial, not theatrical.

## Verification Contract

The following truths are now locked for implementation and validation:

1. Homepage hero structure remains search-first and high contrast.
2. Inline compact search remains the non-home desktop shell pattern.
3. Checkout continues to suppress the shared header.
4. Motion additions must be reduced-motion safe.
5. Scroll-trapping interaction patterns are banned.

## Handoff Summary

Wave 2 implementation should treat this document as a design contract, not inspiration. Any later work that conflicts with these rules requires a new planning decision rather than an implementation-level choice.
